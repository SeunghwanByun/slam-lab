# 실물 카메라 준비 인벤토리

문제: KITTI 기반 학습에서 실물 RGB-D 실내 매핑으로 이동하려면 모델/SDK/OS와 입력 데이터 계약을 먼저 확인해야 한다. 정확한 Astra 모델은 아직 미확인이다.

범위: 읽기 전용 USB/환경 진단, 수집 metadata 양식, 실험 및 평가 설계. 드라이버 설치, 펌웨어 변경, 촬영, SLAM 구동, 드론 제어는 이번 범위 밖이다.

기준 커밋: a865c0d (교재 v2.0.0). 기존 KITTI와 VO/LO는 재사용 학습 자료이며 RGB-D 실측 녹화는 없다.

환경 관측: macOS arm64. 현재 PATH에서 cmake만 확인했으며 ros2/rtabmap/docker는 확인하지 못했다. PATH 검색은 시스템 전체 미설치를 입증하지 않는다. USB 이름 검색에서 Apple 허브만 확인했다. 샌드박스·권한·연결 상태 때문에 장치가 보이지 않을 가능성도 남긴다.

성공 기준 [가정]: 진단 JSON 1개, 단위 테스트 10개 통과, 정확한 모델과 스트림 검증이 없으면 준비 완료로 판정하지 않기. 실물 목표는 60초 정지 녹화와 3회 같은 실내 경로의 지도/치수 비교이며 미수행이다.

2026-11-18 재검사: ioreg의 -l 옵션 누락을 수정하여 USB 제품 6개를 확인했다. 이름 기준 Orbbec/Astra 후보는 0개다. 이전의 빈 목록은 장치 부재를 의미하지 않았다. 사전 점검은 이름 기반 후보 검색이며 지원 여부를 판정하지 않는다.

작은 해결책: 모델 확인 전 SDK를 설치하는 대신 표준 라이브러리 기반 사전 점검을 추가한다. 새로운 SLAM 알고리즘은 필요하지 않으며 baseline 후보는 RTAB-Map이다.
